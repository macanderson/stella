§ 00

Thesis

Stella already refuses to call a task done without a witness — a test that fails on the old code and passes on the new. Autonomous Improvement extends that contract from the code Stella writes to Stella itself. The agent gets better at your work, continuously and unattended, and every claim of improvement is backed by a benchmark run you can replay.

The contract, one level up

Verified improved, not claimed improved. New weights ship only after they survive a gauntlet the incumbent already survived — and every production failure becomes a permanent fixture the next model must pass.

The user experience has to be brutally simple, and everything in this document is subordinate to that:

The golden path

Log in to Oxagen. Pick a workspace. Download Stella. Work. No terminal, no config, no copy-paste — and from that point forward the model behind the agent is being trained on that workspace group's own traces, proven against its own benchmarks, and shipped back without anyone operating anything.

Scope. This paper covers one pillar of the self-improvement story: the Model Refinery — org-scoped model training from Stella traces. The Skill Academy, the Tool Foundry, the Memory Distillery, and the knowledge graph (the Atlas) complete the story and are treated here only where they interlock with training (§01, §12). Each deserves its own paper of this depth.

Posture. Stella stays free, AGPL, and fully functional with no Oxagen anywhere in sight. Everything Oxagen-facing in this design is an adapter behind a port and an open, published protocol — the same discipline as invariant #1 (ports, not concretions). Oxagen Cloud and Oxagen Enterprise are two deployments of the same server-side planes; the client cannot tell them apart.

§ 01

The language of self-improvement

An agent improves along four distinct axes, and conflating them is how self-improvement stories turn to mush. Give each axis a name, a product, a clock, and a verb — then never let one borrow another's claims.

pillar 1
Skill Academy

Learns method — the procedures that work here. Recurring lessons from reflection graduate into skills: codified, reviewable curriculum.

“How is this done here?”

asset skillsclock hours–daysverb teach
pillar 2
Tool Foundry

Learns capability — what the agent can reach for. Awkward, repeated workflows get forged into new tools: authored, tested, registered.

“What can I reach for?”

asset toolsclock daysverb forge
pillar 3 · this paper
Model Refinery

Learns judgment — what the agent reaches for first, without being told. The group's traces are refined into weights: instinct, versioned and provable.

“What do I reach for first?”

asset weightsclock continuousverb refine
pillar 4
Memory Distillery

Learns doctrine — what is true and required here. Raw episodic memory is mined, distilled, and promoted into standing directives and facts.

“What is true and required here?”

asset directivesclock minutesverb distill

On your naming question: keep memory mining as the verb for the first stage — it is exactly right for extraction — and name the pillar the Memory Distillery. The pipeline reads naturally: memories are mined, lessons are distilled, directives are promoted. The product of the pillar is doctrine — the standing rules and facts a session loads before it starts. “Directive building” is the promotion step, not the pillar.

Likewise, Model Tuning undersells the pillar — tuning is a knob; this is a refinery. Model Refinery keeps the industrial register of Foundry and Distillery: crude traces in, refined weights out, continuously. (Alternatives considered in §15.)

▸What the pillars stand on

Four pillars are not the whole language. Three more names complete it — and two of them answer your “am I missing anything?” directly:

the foundation
The Proving Ground

Benchmarks, scars, and proof gates — Harbor tasks, workspace-authored datasets, and every regression fixture a failure ever left behind. Nothing any pillar produces ships on a claim; it ships on an assay run here. This is the missing fifth element in most pillar lists, and it is the one that makes the other four honest.

the substrate
The Trace Lake

The org-scoped store of consented execution traces — the ore every pillar refines. One substrate, four refinements: the Academy reads it for method, the Foundry for friction, the Refinery for judgment, the Distillery for doctrine.

the map
The Atlas

Each workspace's code graph and ontology — the model of the product its repositories represent. You said the knowledge graph “completes the story”: give it this seat and this name. Pillars learn from experience; the Atlas orients that learning in the territory.

the summary
One sentence

“Traces are the ore. Four pillars refine it — method, capability, judgment, doctrine. The Atlas is the map. The Proving Ground is where every refinement is assayed before it ships.”

▸What else you're missing — the disciplines

Pillars are what learns. Around them sit four disciplines — what keeps learning honest. None of these is in your list yet, and each one is a real product surface:

DisciplineThe questionWithout it
Orchestration Which learned asset answers, when? Which pipeline roles run the custom model, which skills load, which directives apply? Pillars compete; a directive contradicts a skill; the tuned model grades its own homework (§06).
Pruning How do stale skills, dead directives, and drifted weights get retired? A system that never forgets accumulates contradictions — doctrine bloats, the prompt prefix grows, cache stability dies.
Attribution When weights, skills, and doctrine all changed this week, which one earned the delta? (The Improvement Ledger + ablation runs, §11.) You can't tell the Refinery from placebo — and you'll fund the wrong pillar.
Governance Who consented to what leaving which machine, and who can revoke it? (The Trace Charter, §10.) The whole flywheel is one privacy incident away from shutdown.
The full lexicon in one line

Four pillars (Academy · Foundry · Refinery · Distillery), one foundation (the Proving Ground), one substrate (the Trace Lake), one map (the Atlas), four disciplines (orchestration · pruning · attribution · governance). One loop.

§ 02

Org, workspace, workspace group

A workspace grows a graph. A workspace group grows a model.

EntityOwnsBoundary it draws
Org Identity, billing, governance, the Trace Charter. The tenancy wall. Nothing crosses it — no traces, no weights, no pooling, ever. One org's experience never trains another org's model.
Workspace The Atlas (code graph + ontology) for one product surface; its repositories; its benchmark datasets; its enrolled devices. What a Stella client connects to. The unit of consent scoping and of benchmark authorship.
Workspace group The training corpus (union of member workspaces' consented traces), the model lineage, the serving alias, the gauntlet history. The unit of model identity. Models are addressed oxagen/<org>/<group>@<channel>.

▸Why groups, and the rules that keep them simple

  • Why not per-org models? An org may want separate models per product family — different domains, different vocabularies, different privacy zones. Pooling a fintech backend with a marketing site pollutes both.
  • Why not per-workspace models? A single workspace rarely generates enough trace volume to train on. Groups pool related work until the corpus clears the volume floor (§06).
  • Membership rules. A workspace may feed many groups (its traces can join several corpora), but each workspace names exactly one serving group — the model its enrolled clients resolve. One knob, no routing table.
  • Groups are org-internal only. There is no cross-org group. A future opt-in “commons” corpus is explicitly out of scope for this design.
§ 03

Requirements, restated

Your must-haves, proof-read and sharpened into testable commitments. Each one names its acceptance criterion — the witness-test habit, applied to a product brief.

R1
Free and open, no strings

Stella ships free under AGPL-3.0 with no build-time or runtime dependency on proprietary software. Every Oxagen touchpoint is an open protocol behind a port; the Uplink is an open-source crate in this repository.

accept: the community build compiles, runs, and passes its gate with every Oxagen endpoint absent; deny.toml unchanged.

R2
Authenticated trace export to a shared workspace

An enrolled Stella authenticates itself (device identity, not pasted keys) and streams its execution traces to the workspace it belongs to — durably, with a per-device cursor, surviving offline gaps.

accept: pull the network mid-session; traces arrive complete after reconnect, exactly once.

R3
Zero-terminal onboarding

Anyone who can log into an Oxagen workspace can download an install package that connects Stella back to that workspace — no terminal opened, no config copied, ever (§09).

accept: a fresh laptop reaches a working custom-model session with zero shell commands and zero pasted strings.

R4
Managed third-party configuration

Oxagen ships per-client configuration packs — schema'd, versioned, editable client by client in the workspace UI (the “collect traces from this client” checkbox lives here) — and Stella applies them through its existing org-managed settings scope (§10).

accept: flipping a pack field in the UI changes enrolled clients' behavior on their next session, with no client-side action.

R5
Custom models from Oxagen Cloud or Enterprise

Stella runs group models served by Oxagen Cloud or an on-prem Oxagen Enterprise identically — oxagen is one more provider adapter with declared cache and reasoning postures and named witness tests, per invariant #8.

accept: the parity matrix has an oxagen row on every axis; swapping Cloud for Enterprise is a base-URL change in a managed pack.

R6
Self-clone benchmarking

Stella clones itself into hermetic sandboxes and runs the gauntlet against candidate weights — fleet fan-out, repeats per task, trace-level adjudication (§07).

accept: a gauntlet verdict is reproducible from its stored traces alone; surface signals are never the evidence.

R7
Workspace-defined benchmarks

Benchmark tasks come from Harbor and from datasets any customer curates inside their workspace. Whatever benchmarks the connected workspace holds, Stella can run.

accept: a task authored in the workspace UI appears in the next gauntlet with no release of anything.

R8
Always-on training, disruption-free deploys

The training pipeline never stops. Candidates that clear their proof gates deploy seamlessly: sessions pin weights at start, new sessions get the new model, nothing restarts (§08).

accept: a promotion during an active session changes nothing in that session and everything in the next.

R9
Never again

A procedure that fails once must not fail the same way twice. Where the world makes error-free repetition impossible, a marked, measured improvement must be demonstrated instead. Delivered as a layered guarantee: doctrine today, scar immediately, weights within days (§12).

accept: every production failure has a scar within one day, and no candidate that fails a scar ever ships.

R10
Versioned, roll-backable models

Every model version records its full lineage — base, adapter, dataset snapshot hash, recipe, gauntlet report, parent. Rollback is an alias flip, instant and boring.

accept: rollback completes in seconds, and the scars stay.

R11
Autonomous operation

No human in the loop to operate — training, proving, promotion, canary, and rollback all run themselves. Autonomy is graduated, not assumed: the human promotion gate retires only after the proof gates have caught every bad candidate for a defined streak (§14).

accept: thirty unattended days with promotions occurring and zero human interventions.

R12
Felt improvement

Improvement must be provable with benchmark data and telemetry — and legible enough to be felt. Every promotion publishes a delta card a developer actually reads (§11).

accept: a developer can answer “what got better this month, and how do you know?” from the feed alone.

§ 05

The trace pipeline

Stella already writes the ground truth this pipeline needs: the session journal (stella-events.jsonl fidelity — every prompt, tool call, result, verdict, and cost, with turn/step structure). The pipeline's job is to move it with consent, label it with outcomes, and never let a projection stand in for it.

▸Five stages, client to corpus

  1. Capture — the journal the engine already emits. No new instrumentation; the trace is the session.
  2. Consent check — the Uplink exports nothing unless a valid, unexpired Trace Charter covers this workspace and the client's managed pack has collection enabled. Two keys, both org-held.
  3. Redact — client-side, before anything leaves: secret scanning, credential pattern kills, configurable path and content denylists from the managed pack. Redaction runs on the developer's machine so unredacted content never exists server-side.
  4. Export — durable, cursor-based streaming (the same discipline as stella usage sync): at-least-once upload, exactly-once ingest, offline-tolerant.
  5. Curate — server-side: dedup, quality gates, outcome labeling, and assembly into content-addressed dataset snapshots so every training run names exactly the bytes it learned from.

▸Labels the traces already contain

The reason Stella traces are unusually good training ore: the agent's own contract generates outcome labels no human ever has to write.

Signal in the traceBecomes
Witness flip (fail→pass) with tamper exclusion Strongest positive label — this trajectory provably did the job.
Pipeline verdicts (triage → … → verdict stage outcomes) Graded outcome labels per stage, per role.
Revise back-edges — a failed execution and its successful revision of the same task Natural preference pairs. The pipeline manufactures DPO data as a side effect of doing its job.
Kept vs. reverted edits; interrupted or abandoned runs Human acceptance labels, harvested without asking anyone anything.
Loop-detector hits, distress signals, budget burn, retry storms Negative process labels — trajectories to train away from.
Reflection lessons and their recurrence Curriculum tags shared with the Academy and the Distillery.
One substrate, four refinements

The same Trace Lake feeds all four pillars. The Refinery consumes trajectories and preference pairs; the Distillery consumes lessons; the Academy consumes recurring method; the Foundry consumes friction. Collect once, learn four ways.

§ 06

The Refinery — training design

▸Base + adapters, not monoliths

Each workspace group's model is a lightweight adapter (LoRA-class) over a pinned open-weight base. This one decision buys most of the product:

  • Per-customer economics. Training an adapter is hours on modest hardware, not a pretraining bill. A thousand groups are a thousand adapters on a handful of shared base deployments.
  • Instant deploys and rollbacks. Adapter hot-swap on the serving plane is a routing change — no model reload, no disruption (R8, R10).
  • Drift containment. A small adapter physically cannot wander far from the base — the first line of defense against catastrophic forgetting, before the Harbor gate even runs (§07).
  • Enterprise fits on-prem. The training-plane hardware profile is a fine-tuning rig, not a datacenter.

Base uplifts (moving a group to a newer base model) are their own gated event: retrain the adapter on the new base, run the full gauntlet, promote like any candidate. The base version is part of the lineage record.

▸Recipe

  • SFT on accepted, witness-proven trajectories — teach the shape of work that verifiably lands.
  • Preference optimization (DPO-class) on revise pairs and kept/reverted edits — teach the difference between the attempt that failed and the revision that didn't.
  • Optional RFT against workspace benchmarks in sandboxed clones, where task volume justifies it — the gauntlet infrastructure doubles as the reward environment.

▸Cadence — always on means three triggers

TriggerFires whenProduces
RollingOn schedule (e.g. nightly), if the corpus moved.The steady-state candidate stream.
VolumeNew labeled trajectories cross a threshold.Early candidates for young, busy groups.
Scar hotfixA new scar lands (§07). A targeted run whose explicit goal is to pass the new scar without regressing the rest — the slow-clock half of “never again” (§12).

▸Role routing — the anti-collusion rule

The tuned model never grades its own homework

The group model serves the worker (and may serve triage and planning). The verifier and witness-author roles run a frozen, independent model — the same separation Stella's pipeline already enforces between worker and verifier. Break this and the flywheel Goodharts itself: a model trained on labels it also assigns will learn to please its own judge, and every metric will improve while the product gets worse.

Consequences: verifier-role traces are excluded from the group corpus, and the gauntlet's adjudication model is pinned per gauntlet run so candidate comparisons stay like-for-like.

▸Cold start

Below the volume floor, a group serves the plain base model plus the fast-clock pillars (doctrine and skills carry the early wins). The Improvement Feed says so honestly — “collecting: 1,204 of ~5,000 trajectories before first training run” — which turns the wait into visible progress instead of silent nothing.

§ 07

The Proving Ground

Three suites, three different questions. A candidate answers all three or it does not ship.

suite 1 · hard gate
The scar suite

Every regression fixture a production failure ever left behind. Pass bar: 100%. Not statistical — absolute. A candidate that reopens any scar is rejected, no matter how good its other numbers are.

suite 2 · the point
The workspace suite

Harbor-format tasks the customer curates in their own workspace (R7), drawn from their real work. Pass bar: improvement over the incumbent with statistical confidence — repeats per task, confidence intervals, never a single-run delta.

suite 3 · the guard
The general suite

Harbor's standard battery. Pass bar: non-inferiority. The specialist must not forget how to be a generalist — this is the catastrophic-forgetting tripwire the adapter architecture backstops.

mechanism
The self-clone gauntlet

Stella runs the gauntlet by cloning itself (R6): fleet fan-out into hermetic sandboxes, one clone on candidate weights, one on incumbent, same tasks, same tools, N repeats. The agent is its own test harness.

▸The scar lifecycle

  1. Failure. A production session fails a procedure — wrong flag, mangled migration, misread convention. The trace holds the whole anatomy.
  2. Authoring. A scar-author (independent model, verifier-side) distills the trace into a Harbor-format fixture: environment setup, the task, and an assertion that fails exactly the way production did.
  3. Validation. The fixture must reproduce — fail against the incumbent under the traced conditions. A scar that can't reproduce its own failure is a false proof and is discarded. (Witness discipline: a fixture that never failed proves nothing.)
  4. Permanence. The scar joins the suite forever. Rollbacks don't remove it. Base uplifts don't remove it. Nothing does.
The emotional line, made mechanical

Stella is allowed to fail a new way. It is never allowed to fail the same way twice — because the second time is a gauntlet rejection, not a production incident.

▸Measurement honesty

The gauntlet inherits this repo's bench discipline wholesale, as product rules:

  • Conclusions come from traces, never surface signals. Every gauntlet verdict is re-derivable from stored run traces; the summary layer is a projection and is treated as one.
  • Operational aborts are named and excluded — an auth failure or a quota exhaustion is not a model loss, and silently counting it as one corrupts the gate in whichever direction is convenient.
  • Like-for-like or reported as confounded. Candidate vs. incumbent differ by exactly one thing: the adapter. Same base, same tools, same tasks, same repeats, pinned adjudicator.
  • Small panels resolve only catastrophes. Promotion thresholds are sized to the suite: a five-task workspace suite gates on regressions, not on decimals. The feed reports the unflattering number when it is the true one.
§ 08

Shipping weights

▸Registry and versioning (R10)

Every version is a complete, immutable lineage record: base model and revision, adapter weights, dataset snapshot hash, training recipe, full gauntlet report, parent version, and the promotion (or rejection) decision. The lineage is a DAG — base uplifts and rollbacks are edges, not erasures. Addressing:

  • oxagen/acme/fintech-core@stable — what enrolled clients resolve by default.
  • oxagen/acme/fintech-core@canary — the fraction under live evaluation.
  • oxagen/acme/fintech-core@v2026.08.07-2 — any pinned version, forever.

▸Seamless, precisely defined (R8)

  • Sessions pin weights at start. A session resolves @stable once and keeps that version to its end — mid-session behavior never shifts under the developer, and the prompt cache stays coherent (byte-stable prompts are an invariant, and a silent weight swap is a behavioral cache-buster even when the bytes hold).
  • Promotion touches only the alias. Serving hot-swaps adapters; nothing restarts; in-flight sessions are untouched. The next session is simply better.
  • Canary is a routing fraction over new sessions, with live telemetry guards (loop-rate, verdict-rate, budget burn vs. incumbent baseline). A canary breach auto-rolls the alias back and files the incident delta card.
§ 09

The golden path — zero-terminal onboarding

R3 is the whole product compressed into ninety seconds. Every step below names what the user does and, underneath, what the system does so they never have to.

Log in to Oxagen, open a workspace

The workspace page shows its repos, its Atlas, its benchmarks — and one button: Download Stella for this workspace.

underneath: nothing yet. The button is the API.

Download the stamped installer

A signed, notarized package for the user's platform, built per-download.

underneath: the package is stamped with a single-use, short-lived enrollment token bound to this workspace and this user — a claim ticket, not a credential. Leaking the installer after expiry leaks nothing.

Run the installer

Installs Stella and the Uplink. No prompts beyond the OS's own.

underneath: the Uplink redeems the token exactly once, mints a device keypair, receives workspace identity, and stores credentials in the OS keychain. The token is now dead.

The workspace configures the client

Nothing to do — this step is invisible.

underneath: the Uplink materializes the org-managed settings document (the scope Stella's 3-way merge already honors): the oxagen provider entry pointing at the group's serving endpoint, the Trace Charter state, and every managed pack — including the trace-collection checkbox (R4).

Work

Open Stella. It is already authenticated, already on oxagen/<org>/<group>@stable, already sending consented traces. The deck shows the connection honestly: workspace: acme/payments · traces: on · model: fintech-core@stable.

underneath: the first trace lands in the lake; the flywheel is turning for this org from minute one.

Manage (or revoke) from the workspace

The workspace lists enrolled devices. Revoking one is a click.

underneath: a revoked Uplink drops the client to community posture — zero egress, group model access off, local Stella fully functional. Enrollment is a lease, never a lock-in.

§ 10

Governance & the zero-egress contract

This section exists because the honest version of this design collides with Stella's own law, and the collision must be resolved in the open, not around it.

Stella's invariant #3 today: zero telemetry egress by default, and even the enrolled Enterprise managed mode may export only a content-free operational rollup — prompts, paths, tool payloads, reasoning, and errors are never exportable, enforced by a reviewed allowlist and a sentinel harness every egress encoder must register with. Training needs the opposite: full-fidelity content. There is no clever encoding that squares that circle, so the design doesn't pretend to — it adds a second, separate, stricter consent channel:

The Trace Charter

A signed org-managed document that authorizes full-fidelity trace export — naming the exact sink, the covered workspaces, and the retention terms. Scoped, revocable, versioned, and visible in-product for as long as it is active: an enrolled deck always shows where traces are going. No charter, no bytes — and the community default remains bit-for-bit zero egress.

  • Two keys, both org-held. Export requires a valid charter and the per-client managed-pack toggle. Either one off, the Uplink ships nothing.
  • Client-side redaction before egress (§05) — unredacted content never exists on the server side. Redaction rules are themselves managed-pack content, auditable per client.
  • Audit trail. Every export batch is logged locally and server-side — device, charter version, byte counts, cursor range. “What left this machine, and under what authority” is always answerable.
  • Same enforcement teeth. The charter path lands as an appended amendment to invariant #3 (append, never renumber) and extends the existing sentinel-harness pattern: a TraceExportEncoder registered in the same reviewed registry, so adding an exportable field fails the gate until a human answers “is this consented content?”.
Called out loud

Amending invariant #3 is the single most consequential change this design asks of Stella. It must ship as its own reviewed PR with its own witness tests — never smuggled in as a side effect of the feature work. If the maintainer rejects the amendment, this design has no fallback and says so.

▸Managed packs — per-client configuration as a product (R4)

The existing three-scope merge (user → org-managed → project, per-field) already has the right seam: the Uplink simply becomes a remote materializer of the org-managed scope. On top of it, managed packs make that scope a product surface:

  • A pack is a schema'd, versioned bundle of settings — Oxagen ships pack definitions; workspace admins edit instances per client in the UI (the trace-collection checkbox is one boolean field in the telemetry pack).
  • Packs are signed and pulled, not pushed — the Uplink refreshes on a cadence and at session start, applies atomically, and logs every transition.
  • The mechanism is open and third-party: any vendor can define a pack schema against the published protocol. Oxagen is the first consumer, not a privileged one — that keeps R1 honest.
§ 11

Felt improvement

Improvement that is real but invisible doesn't retain customers, and improvement that is visible but unproven shouldn't. The product ships proof with feelings attached.

▸The delta card

Every promotion publishes one — in the workspace feed and in the deck:

 improvement feed · acme/fintech-core
★ promoted fintech-core v2026.08.05-1 → v2026.08.07-2 learned from 412 new trajectories · 9 developers · 6 repos scars healed 3 — including “migration runner drops FK ordering” (failed 2026-08-02, never again) workspace 71% → 78% solve rate · 24 tasks × 5 repeats · CI [+2.1, +11.8] general held · Harbor Δ +0.4 (n.s.) — no forgetting rejected first v2026.08.06-1 reopened scar #114 — gate refused it, corpus adjusted rollback one click → v2026.08.05-1 · scars stay regardless

Three properties make the card work: it is written in the customer's own task names, every number links to the gauntlet traces that produced it (replayable, per §07's honesty rules), and it reports the rejection that preceded the promotion — the gate visibly doing its job is what makes the passing number believable.

▸Before / after replay

Any scar or workspace task can be replayed side by side: incumbent's trace against the new version's trace, diffed at the tool-call level. Watching last Tuesday's pit get sidestepped — with the scar that guarantees it stays sidestepped linked underneath — is the moment this product sells itself.

▸The Improvement Ledger

The attribution discipline (§01) made concrete: an append-only record of every learned-asset change — weights, skills, directives, tools — interleaved with every gauntlet result. When the monthly digest says “merge-conflict tasks stopped failing,” the ledger can say which pillar's change did it, and scheduled ablation runs (candidate weights with and without the quarter's new skills) keep that answer honest.

§ 12

Two clocks — how “never again” really works

The brief demands near-real-time learning: a procedure that fails once must never fail the same way again. Weight training alone cannot honestly promise that — its clock is hours to days, and gradient descent generalizes rather than memorizes. The system delivers the promise anyway, as a layered response with two clocks.

T +What firesPillarWhat the developer experiences
minutes The failure's lesson is mined and distilled; a directive is promoted into doctrine. The very next session loads it. Distillery The bleeding stops today. Stella states the rule it learned before repeating the procedure.
hours A scar is authored from the trace and validated — it reproduces the failure against the incumbent (§07). Proving Ground The proof exists before the fix. No future model can ship with this failure mode.
days A scar-hotfix training run produces a candidate that passes the new scar; the gauntlet promotes it (§06, §08). Refinery The lesson becomes instinct — and generalizes to the failure's neighbors, which a directive never could.
after The now-redundant directive is pruned; doctrine stays small; the scar stays forever. Pruning No prompt bloat, no contradiction debt — the fast fix retires when the slow fix lands.
The honest sentence

The directive stops the bleeding today; the scar makes relapse impossible to ship; the weights close the wound for good. Where the world makes error-free repetition impossible — flaky infrastructure, moving targets — the scar's bar is a measured improvement threshold rather than perfection, and the delta card reports it as exactly that.

This is also why the Refinery must not be designed alone (your brief's closing note, made structural): sold as “the model learns in real time,” the pillar over-promises. Sold as one clock of a two-clock system, every claim in it is true.

Risks & open questions

RiskShapeContainment
Reward hacking The tuned model learns to please the grader, not do the work. Frozen independent verifier (§06); held-out suites never trained against; scars authored verifier-side; periodic human spot-audit sampled under the charter.
Catastrophic forgetting The specialist forgets general competence. Adapter-bounded drift + the general suite as a hard non-inferiority gate.
Corpus poisoning One chaotic repo in a group degrades the whole model — or an adversarial contributor plants trajectories. Per-workspace contribution weighting, curation quality gates, and the gauntlet as the final filter — a poisoned candidate still has to beat the incumbent.
Redaction residue Client-side scrubbing is best-effort; a secret slips through. Layered patterns + entropy scanning, charter-scoped retention, server-side re-scan on ingest, deletion propagation into future dataset snapshots. Named honestly: residual risk is nonzero, and the charter says so.
Benchmark overfitting Training toward the workspace suite inflates its numbers. Scars are exact regressions — overfitting them is the point. The workspace suite rotates a held-out split; RFT (when used) trains only on the training split.
Statistical power Small suites can't resolve small deltas; noise promotes or blocks. Repeats per task, CIs on every reported delta, suite-sized thresholds (§07); a five-task panel gates on catastrophe only.
Compute economics Always-on training per group at fleet scale. Adapters over shared bases, trigger-driven runs instead of busy-looping, gauntlet tiering (scar suite is cheap and runs first, rejecting early).
Attribution ambiguity Weights, skills, and doctrine improve simultaneously; credit is unclear. The Improvement Ledger + scheduled ablation gauntlets (§11).

▸Open questions (each becomes an issue at adoption)

  • Which pipeline roles beyond the worker get the group model first — triage? plan? — and on what evidence does a role graduate?
  • Base-model policy: one blessed base per Oxagen release, or per-group base choice? Who approves an uplift, given it invalidates cross-version comparisons?
  • Charter granularity: is per-workspace scoping enough, or do customers need per-repo / per-path carve-outs on day one?
  • Does the Uplink live in this workspace as a crate (stella-uplink) with the protocol spec under docs/wire/, or in a sibling repo like CGP? (The parity-witness obligations of invariant #8 argue for in-tree.)
  • Canary telemetry guards: which live metrics are trustworthy enough to auto-rollback on, given the same measurement-honesty caveats the bench rules exist for?
  • Enterprise hardware floor: what is the minimum on-prem training rig that keeps the scar-hotfix clock inside “days”?
§ 14

Phasing

Five phases, each with a definition of done a fresh agent could verify. Autonomy is earned in P4, not assumed in P0.

PhaseShipsDone when
P0 · Consent & corpus Workspace groups modeled in Oxagen; Trace Charter; invariant #3 amendment PR; Uplink export path; Trace Lake. An enrolled client's traces land org-scoped and workspace-keyed; revoking the charter stops egress at the next session boundary; community build byte-identical in behavior.
P1 · Golden path Stamped installers; Uplink enrollment; managed packs; oxagen provider adapter with parity rows and witness tests. Fresh laptop → working custom-model session, zero terminal, zero copy-paste (R3's acceptance, demonstrated on video).
P2 · First weights Dataset Builder; first adapter training; model registry; human-approved promotion; rollback. One group model beats its base on the workspace suite, is promoted, rolled back, and re-promoted — all three transitions clean.
P3 · Proving Ground Harbor integration; workspace benchmark datasets; scar pipeline; fleet self-clone gauntlet; measurement-honesty rules as code. A deliberately injected failure becomes a validated scar within a day and automatically blocks a candidate built to reopen it.
P4 · Autonomy Continuous training triggers; autonomous promotion; canary + auto-rollback; Improvement Feed and delta cards; ablation cadence. Thirty unattended days: promotions occurred, zero human interventions, zero scar regressions in production, and the feed explains itself.
The graduation rule

The human promotion gate in P2–P3 is scaffolding, and its removal has a witness: it retires only after the proof gates have independently rejected every bad candidate the humans also rejected, for a defined consecutive streak. Autonomy is demonstrated, then granted — never granted, then hoped for.
