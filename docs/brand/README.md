# Brand

The identity is a wordmark and one mark. Nothing else. Every file in this
directory is generated by [`build.py`](build.py) — **do not hand-edit the
assets**; change the generator and run `make brand`.

## The wordmark

Lowercase `stella`, set in **Space Grotesk Medium** (weight 500) and tracked
**−0.02em**, converted to outlines.

Space Grotesk is drawn from Space Mono, so it keeps a monospace's technical
skeleton while setting tight as a proportional face — the right voice for a
terminal tool, and it carries the name honestly. Outlining it means nothing at
build or render time depends on a font being installed, and the wordmark can
never fall back to something else.

The wordmark is the primary logo. **It is expected to carry the brand alone.**
Reach for the lockup only when a layout genuinely needs a mark beside it.

## The mark

A six-arm concave asterisk. It reads two ways at once, which is the whole point:
`*` is a glob, a wildcard, the opening of a doc comment — and it is a star.

Use it **only** where a square or very small footprint rules the wordmark out:
favicons, app icons, a 26px header slug. It is not a standalone logo.

## Colour

Monochrome, on purpose.

| Token | Value | Use |
| --- | --- | --- |
| Ink | `#0A0A0A` | letters and mark on a light ground |
| Paper | `#FAFAFA` | letters and mark on a dark ground |

There is no brand hue in the logo. This repo carries three rival palettes — the
docs site's neutral paper-&-ink (`stella-docs/src/app/global.css`), the TUI's
aurora-on-navy (`stella-tui/src/theme.rs`), and the observatory's cyan
(`stella-observatory/src/assets/index.html`). A monochrome mark sits correctly
on all three instead of arbitrating between them. Leave it that way until those
three are reconciled; a coloured logo would just become a fourth opinion.

## Files

Prefer `wordmark.svg` / `mark.svg` (both `currentColor`) wherever the consumer
can inherit colour — inline SVG, or a Rust/React component. The `-ink` / `-paper`
cuts exist for `<img>` and `srcset`, where `currentColor` would resolve to black
regardless of the surrounding theme.

| File | What |
| --- | --- |
| `wordmark.svg` | wordmark, `currentColor` |
| `wordmark-ink.svg` · `wordmark-paper.svg` | wordmark, fixed colour |
| `mark.svg` | mark, `currentColor` |
| `mark-ink.svg` · `mark-paper.svg` | mark, fixed colour |
| `lockup-ink.svg` · `lockup-paper.svg` | mark + wordmark, horizontal |
| `favicon.svg` | mark on a rounded ink tile, 200² |
| `appicon.svg` | mark on a squircle ink tile, 512² |

Icons carry a tile rather than sitting on transparency, so a favicon stays
legible against any browser-tab colour.

## Clear space and minimum size

Keep clear space of at least the wordmark's cap height on every side. The
wordmark stays clean down to about **56px** wide (17px tall) — that is the
floor, not the target. Below it, use the mark instead. The docs-site nav sets it
at 67px (20px tall), which is a good reference for a UI chrome size.

Don't: recolour it, outline it, add a gradient or shadow, stretch it, set the
name in another face, or rebuild the wordmark from live text.

## Regenerating

```sh
make brand
```

Needs `fonttools` and `uharfbuzz` (pip) plus `rsvg-convert`
(`brew install librsvg`). The typeface is fetched once from Google Fonts,
verified against a pinned SHA-256, and cached under `.cache/` (gitignored).

`build.py` is the only place the geometry lives. It writes, in one pass:

- these source assets
- the site's copies under `stella-docs/public/brand/` — copied, not duplicated
  by hand, which is what let the previous generation drift out of step
- the favicon/PWA/app-icon rasters under `stella-docs/public/icons/` and the
  Next.js file-convention icons in `stella-docs/src/app/`
- `stella-docs/src/components/brand.tsx`, so the landing page's inline mark and
  the generated OG card share the exact paths in these SVGs
- the mark and wordmark embedded in the observatory binary

## Typeface

**Space Grotesk** by Florian Karsten, [SIL Open Font License 1.1][ofl]. The
logo ships as outlines, so the repo vendors no font binary. The docs site loads
the family via `next/font/google` for brand-name text (`.lp-brand-face`), so the
name in running copy matches the logo.
