01 · why stella

a definition of done you can re-run.

stella is a single static rust binary with one uncommon idea: an agent should have to prove that the change it made is the change that fixed the problem — and everything else exists to make that proof cheap, local, and reproducible.

proof, not vibes

verify_done replays your new test against yesterday's code in a shadow worktree at git HEAD. it must fail there and pass on the change — a green suite alone is never accepted. no test in hand? an independent witness author writes one: tamper-excluded, mutation-checked, assertion-screened.

one loop you can read

no swarm, no coordinator, no hidden control plane. plan → fan tools out in parallel → observe → compact → repeat. the engine does zero i/o — every decision is a synchronous function you can property-test.

byok. nine providers + local.

anthropic, openai, gemini, xai, deepseek, z.ai, openrouter, vertex, bedrock — or any openai-compatible local server. per-agent routing: worker on one key, judge on another. no account. no gateway.

a budget that means it

--budget is a hard dollar boundary that aborts cleanly between steps — never mid-tool. a cap can't corrupt a half-written edit.

a code graph, not grep

tree-sitter symbol + import index across ten languages. definitions, references, importers — answered offline, no key needed.

your disk is the database

every event, token, and touched file lands in local sqlite. stella inspect replays the exact context any past call was sent, verified against digests. nothing phones home.

02 · context prs

knowledge that ships like code.

every team rediscovers its own rules one agent session at a time. stella turns what it learns into reviewable diffs — durable steering that rides pull requests, carries its evidence, and answers to git. rules load into a byte-stable prompt at cache prices; guard-* rules block at the tool boundary itself.

03 · the self-improvement loop

stella makes stella better. and has to prove it.

an agent that grades its own homework is always improving. so every candidate improvement — a mined rule, a distilled skill, a self-authored tool, a policy change — is generated cheap, evaluated against held-out tasks it didn't train on, and promoted only on measured lift. context prs are the publication step; the witness gate is the floor.
