## The gap

Stella's system prompt gives the model rich *project* orientation (scripts index, graph-derived layout, memories, exploration index — `assemble_system_prompt`, `prompt.rs:208`) but no *session environment* identity: not the working directory, platform, shell, OS version, whether the tree is a git repo, which model is running, or its knowledge cutoff. The model discovers its cwd by running `pwd`, guesses shell dialect, and has no basis for judging whether its trained knowledge of a fast-moving dependency is stale.

All of these are session-constant, so they are compatible with the byte-stable prefix discipline (L-E8) — this is not the CLAUDE.md/date problem. The one genuinely volatile item, today's date, stays out of the prefix and can ride the volatile recall block if wanted.

## What the comparator carries

An `# Environment` block: cwd (+ "this is a worktree — do not cd to the original root" when applicable), additional working directories, git-repo bit, platform, shell (with a Windows note to use Unix syntax where applicable), OS version from uname, model marketing name + exact model ID, and the knowledge cutoff date. Cheap (~100 tokens), cached, and it eliminates a whole class of first-turn discovery calls and shell-dialect mistakes.

## How to port it

Append an `append_session_environment` section in `assemble_system_prompt` alongside scripts/orientation: computed once per session from values that cannot change mid-session (cwd, platform, shell, OS, model ref resolved by the router for the session's role, cutoff from a per-model table). Worktree awareness matters extra for Stella: fleet workers and pipeline candidates run in worktrees (`build_system_prompt` already takes `workspace_root` for exactly this reason), and a model that `cd`s back to the primary checkout defeats the isolation.
